# Sidekick

Use `sidekick doctor ENGINE`, then inspect native control evidence with `sidekick capabilities ENGINE --model MODEL --json` before delegating. Start work with `sidekick spawn ENGINE NAME --dir PATH -- "PROMPT"`; use separate control axes (`--model`, `--provider`, `--transport`, `--effort`, `--permission`, `--sandbox`, `--workspace-trust`) instead of treating legacy `--mode` as a universal semantic. Start one background `sidekick wait NAME... --all --json` for a batch, continue independent work, and harvest with `sidekick result NAME --json`. Check `sidekick status --json` and terminal `exitCode`; status shows active runs plus bounded recent history unless `--all` is supplied. Use `sidekick clean --dry-run` before retention deletion, especially when state diagnostics report legacy or unreadable directories; use `sidekick migrate --json` to preview legacy conversion and require explicit `--apply` before mutation. Add `--quarantine` for unsupported state and `migrate NAME --restore --apply` to recover a quarantined entry. Continue with `sidekick send NAME -- "FOLLOW-UP"`; `send` accepts no control override because persisted controls are immutable. Use `sidekick adopt` for an existing session, `sidekick tail` for live output, `sidekick cancel` for a resumable full-tree stop, and `sidekick clean` for terminal-run retention. Install harness guidance with `sidekick skill install HARNESS`.

Each new run records `requested`, `applied`, and `effective` observations. An argv flag is not evidence of provider-reported `effective` state. Unsupported, malformed, model-dependent-unverified, or runtime-version-mismatched explicit controls fail closed with exit 2 before prompt/cwd/discovery/store/worker side effects. Devin family slug `glm-5.2` and variant UID `glm-5-2` are distinct; never silently alias them. `normal` is the current Devin default alias for native `auto`; do not use `--mode high` as an effort setting.

For adversarial review, use a read-only reviewer prompt with explicit no-edit/no-commit/no-push constraints and a catalog-probed model id. For Devin GLM-5.2 High use the currently evidenced model id from `sidekick doctor devin` / the live catalog (family slug `glm-5.2` and variant UID `glm-5-2` are distinct; never invent an alias). Pair high-effort final reviewers only when their configured effort and model are recorded. Require `sidekick wait`, `sidekick result --json`, exit code, and independent diff/test verification before accepting a review.

Do not concurrently spawn workers with the same `--dir`. Harness session discovery and workspace state can be directory-scoped, causing lock contention, accidental serialization, or overlapping edits. For real parallelism, give each worker a separate git worktree and pass that worktree as `--dir`. If separate worktrees are unavailable or tasks must share a working tree, run one worker at a time and reuse its session with `sidekick send`.
