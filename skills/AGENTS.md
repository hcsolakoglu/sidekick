# Sidekick

Use `sidekick doctor ENGINE`, then delegate with `sidekick spawn ENGINE NAME --dir PATH -- "PROMPT"`. Start one background `sidekick wait NAME... --all --json` for a batch, continue independent work, and harvest with `sidekick result NAME --json`. Check `sidekick status --json` and `exitCode`; status shows active runs plus a bounded recent history unless `--all` is supplied. Use `sidekick clean --dry-run` before retention deletion, especially when state diagnostics report legacy or unreadable directories; use `sidekick migrate --json` to preview legacy conversion and require explicit `--apply` before mutation. Add `--quarantine` for unsupported state and `migrate NAME --restore --apply` to recover a quarantined entry. Continue with `sidekick send NAME -- "FOLLOW-UP"`; use `sidekick adopt` for an existing session, `sidekick tail` for live output, `sidekick cancel` for a resumable full-tree stop, and `sidekick clean` for terminal-run retention. Install harness guidance with `sidekick skill install HARNESS`. Keep task scopes independent and include constraints plus verification in every prompt.

Do not concurrently spawn workers with the same `--dir`. Harness session discovery and workspace state can be directory-scoped, causing lock contention, accidental serialization, or overlapping edits. For real parallelism, give each worker a separate git worktree and pass that worktree as `--dir`. If separate worktrees are unavailable or tasks must share a working tree, run one worker at a time and reuse its session with `sidekick send`.
