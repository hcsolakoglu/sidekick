# Sidekick orchestration

Use Sidekick for bounded delegation. Run `sidekick doctor ENGINE` and `sidekick capabilities ENGINE --model MODEL --json` before selecting a native control. Spawn with an exact scope and verification command, using separate axes (`--model`, `--provider`, `--transport`, `--effort`, `--permission`, `--sandbox`, `--workspace-trust`) rather than assigning universal meaning to legacy `--mode`. Start one background `sidekick wait NAME... --all --json`, then harvest `sidekick result NAME --json`; check terminal status and `exitCode`. Continue with `sidekick send`; use `adopt`, `tail`, or `cancel` for existing, live, or stopped work. `send` does not accept control overrides because persisted controls are immutable.

Controls persist `requested`, `applied`, and `effective` observations. An argv flag alone is not provider evidence. Unsupported, malformed, model-dependent-unverified, or runtime-version-mismatched explicit values fail closed with exit 2. Devin `glm-5.2` family and `glm-5-2` variant identifiers are not silently aliased; do not use `--mode high` as effort.

Never concurrently spawn workers with the same `--dir`: harness session discovery and workspace state can be directory-scoped, causing lock contention, serialization, or overlapping edits. For actual parallel execution, create a separate git worktree for each worker and use that worktree as `--dir`. When worktrees are unavailable or edits must share a tree, run one worker at a time and reuse its session with `sidekick send`.
